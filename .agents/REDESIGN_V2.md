Gas bung. Aku bikin versi yang terasa lebih seperti **internal design directive perusahaan beneran**, bukan sekadar prompt buat AI. Jadi Codex membaca ini bukan sebagai “buat landing page keren”, tapi sebagai **aturan arsitektur visual + positioning + execution protocol**.

Simpan sebagai:

`/.agents/REDESIGN_V2.md`

````md
# SYSTEMIFY / REDESIGN V2
## Operational Editorial Design Directive

> **Status:** Active Design Direction
> **Repository:** `mify-id`
> **Scope:** Public Website + Authenticated Product + Brand System
> **Priority:** Clarity → Identity → Evidence → Usability → Decoration
>
> This document defines the next visual and product direction of Systemify.
> Every agent working on UI, copy, interaction, layout, or product presentation

# 00 / NORTH STAR

Systemify must stop looking like a company that merely
"makes websites, AI, and digital products."

Systemify builds:

> **the systems behind how businesses operate.**

Systemify exists to turn:

- manual work
- disconnected tools
- scattered communication
- repetitive administration
- unclear operational processes

into:

- structured workflows
- usable software
- connected systems
- automation
- measurable operations

The redesign must communicate this idea within the first few seconds.

# 03 / DESIGN DIRECTION

Internal design language:

# OPERATIONAL EDITORIAL

The interface should feel like a combination of:

- engineering documentation
- technical publications
- architecture diagrams
- industrial systems
- operating software
- modern editorial design

It must NOT feel like:

- a crypto landing page
- a futuristic AI startup
- a generic SaaS template
- a Dribbble dashboard
- a cyberpunk interface
- a creative-agency template
- a page generated from a generic AI prompt

---

# 04 / DESIGN PRIORITY

Every design decision follows this order:

```text
INFORMATION
↓
HIERARCHY
↓
STRUCTURE
↓
EVIDENCE
↓
INTERACTION
↓
DECORATION
````

Decoration is always last.

Never reverse this hierarchy.

---

# 05 / PROFESSIONAL RESTRAINT

Professional does NOT mean:

* more shadows
* more animations
* more gradients
* more cards
* more glass
* more effects

Professional means:

* better hierarchy
* better typography
* better spacing
* better writing
* better information structure
* stronger consistency
* clear interaction
* less visual noise

Systemify should look intentionally restrained.

---

# 06 / COLOR SYSTEM

## Primary Environment

Use neutral surfaces for most of the experience.

Recommended hierarchy:

```text
Neutral / Ink / Off-White    80%
Systemify Blue               15%
Signal Lime                   5%
```

---

## Brand Colors

### SYSTEMIFY BLUE

Used for:

* major brand moments
* important section surfaces
* selected interface states
* key navigation signals
* brand emphasis

Blue should feel authoritative.

Do NOT scatter blue everywhere.

---

### SIGNAL LIME

Lime is no longer decorative.

Lime means:

* important
* active
* operational
* selected
* actionable
* system signal

Lime should be rare enough that when it appears,
the user immediately notices it.

# 08 / SHAPE LANGUAGE

The previous system relied too heavily on rounded containers.

This must change.

## Radius is contextual.

Suggested hierarchy:

```text
2–4px
Editorial markers
Small highlights
Technical labels

6–10px
Inputs
Compact panels
Operational UI

12–16px
Major product surfaces
Modals
Functional cards

999px
Buttons
Status pills
Explicit pill-shaped controls only
```

Do NOT use `rounded-[24px]` everywhere.

Do NOT turn every text block into a card.

Different object types should have different geometry.

---

# 09 / HIGHLIGHT SYSTEM

Text highlights must feel editorial,
not like UI badges.

Avoid:

```text
[ how businesses operate ]
```

when the background behaves like a large rounded card.

Prefer:

```text
how businesses operate
                     ━━━━━
```

or:

```text
how businesses
operate
██████
```

or a restrained offset marker behind a keyword.

Rules:

* highlight only meaningful phrases
* do not highlight complete paragraphs
* avoid `rounded-full`
* avoid excessive width
* highlight must not compete with the text itself

---

# 10 / TYPOGRAPHY

Typography should carry most of the visual identity.

Use large differences in scale.

---

## Display

For major statements.

Characteristics:

* large
* dense
* confident
* strong line breaks
* minimal decoration

---

## Body

Body copy must be:

* readable
* concise
* high contrast enough
* visually quieter than headings

Avoid tiny gray text that exists only to look sophisticated.

---

## Labels

Uppercase labels are allowed,
but must be used intentionally.

Example:

```text
01 / POSITION
02 / SYSTEMS
03 / PROCESS
```

Do not put uppercase eyebrow text above every heading.

---

## Monospace

Reserve monospace for:

* identifiers
* system states
* timestamps
* technical metadata
* deployment information

Example:

```text
SYS–024
PRODUCTION
00:42:18
```

Monospace should signal system information,
not decoration.

# 22 / CARDS

Cards are containers,
not a design style.

Use a card only when:

* the content is independently actionable
* the information belongs together
* the object represents an entity
* the object requires its own state
* containment improves usability

Examples:

GOOD:

* project
* client
* invoice
* deployment
* task
* brief
* order

BAD:

* headline
* one sentence
* generic feature
* random statistic
* decoration

---

# 23 / EFFECTS

No visual effect is mandatory.

Every visual effect requires justification.

---

## Glow

Use only for:

* active system state
* focus
* rare brand emphasis

Never:

> glow behind every card.

---

## Blur

Use only when:

* separating floating surfaces
* preserving context behind overlays

Do not use glassmorphism everywhere.

---

## Shadows

Prefer subtle depth.

Large neon shadows should be rare.

---

# 24 / MOTION

Systemify should feel alive,
not animated.

Motion should explain something.

Allowed reasons:

```text
STATE CHANGE
NAVIGATION
FEEDBACK
DIRECT MANIPULATION
HIERARCHY CHANGE
PROGRESS
```

Not allowed reasons:

```text
because Framer Motion exists
because the page looked empty
because animation looks modern
```

---

## Avoid

* continuous pulse
* floating decorative objects
* every-section scroll reveal
* every-button scaling
* random rotation
* repeated entrance animations

# 32 / ACCESSIBILITY

Accessibility is part of design quality.

Requirements:

* visible focus states
* semantic HTML
* sufficient contrast
* keyboard navigation
* correct labels
* meaningful button names
* reduced motion support
* no interaction that depends exclusively on color

Traffic-light status must include text or icon meaning.

Never communicate status through color alone.

# 35 / AGENT EXECUTION PROTOCOL

Before touching UI:

1. Read `.agents/AGENTS.md`
2. Read `.agents/REDESIGN_V2.md`
3. Read current relevant source files
4. Read `.agents/roadmap.md`
5. Understand existing backend behavior
6. Identify the active implementation phase

Before coding, state:

```text
OBJECTIVE

FILES TO CHANGE

WHAT STAYS

WHAT CHANGES

WHAT WILL BE REMOVED

RISKS

VALIDATION PLAN
```

Then implement.

---

# 36 / CONTINUOUS EXECUTION

Do not stop at the first minor error.

When an implementation problem appears:

```text
IDENTIFY
↓
UNDERSTAND
↓
FIX
↓
VERIFY
↓
CONTINUE
```

Do not abandon the phase simply because:

* a build fails
* an import breaks
* Tailwind class changes
* a dependency behaves differently
* responsive behavior requires iteration

Resolve reasonable implementation problems
before declaring the phase blocked.

---

# 37 / CHANGE CONTROL

Do NOT rewrite working backend logic
just because the UI is changing.

Do NOT:

* rename routes unnecessarily
* rewrite controllers without reason
* change database schema for visual convenience
* replace libraries without justification
* rebuild working features from scratch

Visual redesign must preserve functional integrity.

---

# 38 / DEPENDENCY RULE

Do not add a package simply because
it makes a design easier.

Before installing anything,
verify whether the current stack can solve it.

Preferred existing capabilities:

```text
React
Tailwind
Inertia
Framer Motion
Phosphor / Lucide
Native Browser APIs
```

New dependencies require a specific reason.

---

# 39 / BUILD VALIDATION

After each implementation phase:

Run:

```bash
npm run build
```

And relevant backend checks.

Do not finish a phase with known compilation errors.

Also inspect:

```text
desktop
tablet
mobile
```

A successful build does not automatically mean
the design is correct.

---

# 40 / VISUAL REVIEW QUESTIONS

Before considering a section complete:

### CLARITY

* Can I understand the purpose immediately?
* Is the primary information obvious?
* Is anything competing with it?

### IDENTITY

* Does this feel like Systemify?
* Or could this belong to any SaaS startup?

### RESTRAINT

* Can any decoration be removed?
* Are effects solving a problem?
* Are there too many containers?

### EVIDENCE

* Are we showing proof?
* Or only making claims?

### INTERACTION

* Does every interaction communicate feedback?
* Is motion helping understanding?

### RESPONSIVE

* Does mobile feel intentionally designed?

---

# 41 / AI-SLOP DETECTOR

Stop and reconsider if the interface starts accumulating:

```text
✓ giant glowing gradients
✓ four matching icon cards
✓ excessive glass panels
✓ floating decorative icons
✓ neon everywhere
✓ generic AI copy
✓ excessive pill badges
✓ giant rounded containers
✓ fake dashboards
✓ arbitrary bento grids
✓ every section animating on scroll
✓ decorative sparkles
✓ identical spacing everywhere
```

One occurrence may be legitimate.

A collection of them is usually a warning sign.

---

# 42 / THE FIVE-SECOND TEST

A first-time visitor should understand within approximately five seconds:

```text
WHAT IS SYSTEMIFY?

WHAT DOES SYSTEMIFY BUILD?

WHO IS IT FOR?
```

Desired answer:

> Systemify builds custom digital systems and automation
> around how businesses actually operate.

If the page communicates only:

> modern technology company

the design has failed.

---

# 43 / SUCCESS CRITERIA

The redesign succeeds when:

* Systemify has a recognizable visual identity
* visitors understand the business immediately
* real systems are more visible than marketing claims
* BUILD / AUTOMATE / OPERATE becomes recognizable
* lime behaves as a signal rather than decoration
* public pages feel editorial
* admin pages feel operational
* components are semantically structured
* mobile feels intentionally designed
* animation remains restrained
* the interface does not resemble a generic AI-generated landing page
